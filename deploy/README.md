# Remote deployment (EC2 + Cloudflare Tunnel)

Runs the bridge and the MCP server as two systemd services on one host and
publishes the MCP server at `https://local.sheiksadi.dev/whatsapp/mcp` through
a named Cloudflare Tunnel. Nothing listens on a public interface.

```
Claude Code ──https──> Cloudflare ──tunnel──> cloudflared (local-tunnel.service)
                                                │  path ^/whatsapp
                                                ▼
                     whatsapp-mcp-server.service  127.0.0.1:8791  (remote.py, bearer auth)
                                                │  REST + bridge token
                                                ▼
                     whatsapp-bridge.service      127.0.0.1:8790  (whatsmeow) ──> WhatsApp
                                                │
                                   $DATA_DIR/store/{whatsapp.db,messages.db,media}
```

## Routes (prefix `BASE_PATH`, default `/whatsapp`)

| Route | Auth | Purpose |
|---|---|---|
| `/whatsapp/mcp` | `Authorization: Bearer <token>` | MCP, Streamable HTTP |
| `/whatsapp/setup/qr` | Bearer, or Basic with the token as password | Linking QR as HTML (auto-refresh) or `?format=png`; 409 once paired |
| `/whatsapp/healthz` | none | `{"status":"ok"}` — process liveness only |

The token is compared in constant time and is never accepted in a URL. Basic
auth exists only on `/setup/qr`, so a browser can show the page (it prompts
once and resends the header on each refresh); user name is ignored.

The server's Host-header check allows only `PUBLIC_HOST` and loopback.

## Secrets and state

- `MCP_AUTH_TOKEN`: SSM Parameter Store SecureString `/whatsapp-mcp/auth-token`
  (`MCP_TOKEN_PARAM`). `bin/mcp-start.sh` reads it at every start with the EC2
  instance role and creates it (random 256-bit, `--no-overwrite`) on the first
  start. IAM: `SheikSadi/aws-infra` `terraform/whatsapp_mcp.tf`.
- Bridge ↔ server token: `$DATA_DIR/store/.bridge-token` (0600, generated by the bridge).
- `DATA_DIR` (default `~/.whatsapp-data`, 0700) holds both SQLite databases and
  media; it is on the root EBS volume, which is snapshotted daily (aws-infra).
- `~/.config/whatsapp-mcp.env` holds non-secret settings only (`env.example`).

## Install / deploy

Needs Go 1.26 (`/usr/local/go`), gcc (CGO for SQLite), `uv`, the AWS CLI and
`cloudflared` (with `~/.cloudflared/cert.pem` from `cloudflared tunnel login`).

```bash
git clone https://github.com/SheikSadi/whatsapp-mcp ~/.local/share/whatsapp-mcp-deploy
cd ~/.local/share/whatsapp-mcp-deploy
make -C deploy build install restart

# Tunnel (once)
cloudflared tunnel create local
sed -e "s|__TUNNEL_ID__|<uuid>|g" -e "s|__HOME__|$HOME|g" deploy/cloudflared/local.yml.example > ~/.cloudflared/local.yml
cloudflared tunnel route dns local local.sheiksadi.dev
sed -e "s|__USER__|$USER|g" -e "s|__HOME__|$HOME|g" deploy/systemd/local-tunnel.service | sudo tee /etc/systemd/system/local-tunnel.service
sudo systemctl daemon-reload && sudo systemctl enable --now local-tunnel
```

Later: `make -C deploy deploy` (pull, build, install, restart, status); also
`update`, `restart`, `status`, `logs`, `test`.

## Pairing

Open `https://local.sheiksadi.dev/whatsapp/setup/qr`, enter any user name and
the token as password, then in WhatsApp → Linked Devices → Link a Device scan
the code. The page follows the bridge's live code (codes rotate about every
20 s) and asks the bridge for a new linking round when the last one timed out.
Once linked it answers 409. After the phone removes the device, the same page
offers a new code.

Token for this: `aws ssm get-parameter --name /whatsapp-mcp/auth-token --with-decryption --query Parameter.Value --output text`
(admin login or on the instance).

## Clients

```bash
claude mcp add --transport http whatsapp https://local.sheiksadi.dev/whatsapp/mcp \
  --header "Authorization: Bearer $WHATSAPP_MCP_TOKEN"
```

Claude Desktop's own connectors need OAuth; use `mcp-remote` in
`claude_desktop_config.json` instead:

```json
{"mcpServers": {"whatsapp": {"command": "npx", "args": ["-y", "mcp-remote",
  "https://local.sheiksadi.dev/whatsapp/mcp", "--header", "Authorization:${AUTH}"],
  "env": {"AUTH": "Bearer <token>"}}}}
```

`send_file`, `send_audio_message` and `download_media` work with paths on the
server (`WHATSAPP_MEDIA_ROOTS`, `DATA_DIR/store`), not on the client.
